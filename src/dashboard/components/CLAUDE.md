# Dashboard Components Organization

This folder is organized by dashboard area. Keep files near the UI surface that owns them; use `shared/` only when more than one area uses the same piece.

## Folders

## Lessons Learned

- **2026-07-27 (wave 6, on top of the four-wave entry below): the gate banner is DELETED — the decision lives inline in the stream with a floating locator, Data and Edit Data are one surface again, OCR fields correct in place, and an identity gate shows the candidates as evidence (`dev/rebuild-demo/{DemoLogPanel,DemoContextRail,DemoEvidence}.tsx`, `demo-wire.ts`, `demo-evidence-wire.ts`, `demo-data.ts`, `ds/tokens.css`).** Six operator notes on the log panel, all of them about the same thing: the panel was TELLING the operator about a decision in three places and letting them ACT on it in one. **(1) The banner was a DUPLICATE, not information.** The decision was drawn twice — a tall banner above the tabs and, at the moment it occurred, the same title, the same copy and the same buttons inline in the log stream (verified on the write-parked run `se-134802-c2d7` and the identity-approval run `se-140211-9f3a`). Operator: *"for these long like warnings/manual submitting stuff, just put in log panel for me to approve and not as a separate piece at the top… just give me a brief like dismissable floating notification square on like a corner of the panel."* So the banner is gone and `GateCardView` grew into `InlineDecision` — the full surface (title, age, the `note` the narrow card never rendered, candidates, staged writes, both park resolutions, every banner pill), `tabIndex={-1}` + `dsFocus` so it can be focused, sitting where the lines that argue for it are. **What replaced the banner is a different KIND of thing, not a smaller banner:** the header keeps its status pill (`Waiting on you · 33m 50s`), the outcome line is now rendered UNCONDITIONALLY (its old suppression existed only because the banner repeated it) and its `Review` / `Resolve` pill is intercepted in `handleAction` to travel to the decision instead of posting a result, and a `DecisionNotice` appears in the tab body's top-right ONLY while the decision is out of reach. **That last condition is what stops the notice being the banner again:** an `IntersectionObserver` on a CALLBACK ref (the anchor unmounts on every tab change, so a plain ref holds a detached node) — `noticeShown = gate && !dismissed && !inView`. Dismissal is per row+tab and re-arms on either change, so a dismissed reminder never becomes an unreachable decision. Pressing it calls `onTab(decisionTab)` then bumps a nonce an effect watches, because the anchor does not exist yet when the click fires; `decisionTab` is `review` on a review panel (whose approve bar carries the same anchor) and `logs` everywhere else. **This overrides ratified D18** (the composite `Needs you` as the loudest element, never behind an interaction) and touches **D12**; both need amending in `docs/rebuild/03-tracker-dashboard.md` §9. **(2) A floating tint must be layered, never applied to the floating element.** `--ds-status-waiting-bg` is `color-mix(… , transparent)`, so painting it onto the `FloatingSurface` left the log stream legible THROUGH the notice — it read as a rendering fault. The opaque `--ds-surface-overlay` stays on the surface and the tint goes on an inner div. The notice sits at `dsLayer.sticky`, deliberately BELOW the toast layer: a reminder must never cover a failure. **(3) Data and Edit Data are ONE surface again — the `Edit & re-run` Dialog is deleted.** Operator: *"we also need the edit data and data tab to be together so i can have a feel of how its like to edit the data to either continue the run or start a new run with custom data."* Reads are corrected in place in the rail's ledger; writes are still never editable; CAS-on-generation, the held-and-re-offered patch, `editPolicyFor`'s always-shown reason and the audited freshness override all moved into the section unchanged (the freshness confirm stays a dialog — it is a question with a typed answer and two mutually exclusive exits). 348px is tight to type into, so the surface WIDENS (`--ds-w-context-rail-wide: 520px`, a `dataExpanded` flag on `useContextRail` that retargets the region's grid column and hides the rail's other three sections) rather than hiding in a modal. **The row is deliberately the old Data TAB's row** (operator: *"the data row should look like how it did in the log panel"*) — direction icon · quiet label · value in tabular mono · badges · system · clock — narrowed, not redrawn: the clock and the lock TAG fold away below a 26rem CONTAINER query and return when expanded, because at 316px a two-badge write row was truncating the VALUE, the one thing on the line that cannot be recovered from elsewhere. **(4) TWO outcomes, kept apart by the SERVER.** New wire command `continue-with-data` (save the checkpoint AND release the SAME run from where it stopped — same runId, same lineage, same receipt) beside `rerun-with-existing-data` (a NEW run, its own trace and receipt). `deriveActions` sends `continue-with-data` only where there is work left to release (`failed`/`cancelled`) and `edit-checkpoint` ("Save corrections") otherwise, so exactly one save arm and one primary exist on the surface at a time. **It also closed a real hazard:** the old policy offered `rerun-with-existing-data` on a PARKED row, i.e. "start a run from this data" on a write whose outcome is unknown — the duplicate-termination path D20 exists to prevent. Parked is now sent no `data` command at all; its only exits stay the two typed park resolutions. **(5) An OCR correction changes the value's PROVENANCE.** `DemoRecordField.source` gained `operator`, and a field the operator types over renders `YOU` instead of `PAPER` **and drops the model confidence to an em dash** — a hand-typed value is not a 0.97 paper read, and the confidence that belonged to the value it replaced must not follow the new one. The machine's reading survives on the correction, which is minted by the ONE pure builder `buildRecordCorrections` (`demo-wire.ts`, keyed `<recordId>:<field>`), counted on the approve bar and carried in the approve command's payload — so the number shown and the list sent cannot be two derivations. Fields that were LOOKED UP rather than read off the page are locked with the reason on the row. **(6) An identity gate shows the candidates as evidence, and supports more than two.** `GateCandidateSpec` (`eid` / `matchedOn` / `captureId`) replaces the inline candidate triple; captures are fetched BY ID from `candidateCaptureFor` in `demo-evidence-wire.ts`, so a candidate whose id resolves to nothing renders "No capture — this was never on a page" instead of borrowing its neighbour's (the typed-name candidate on `sep-l-2` is exactly that case, and it is the honest answer, not an omission). The viewer is the existing `CaptureLightbox`, now exported, so the "metadata, not bytes" honesty copy has one home. The layout is a `grid` on container queries, and `i9-m-11` was widened to THREE candidates with a third `pick-eid:` option so the surface is proved against a set that is not a pair. **Backend capabilities this assumes** (for whoever writes them into the rebuild plans): a per-candidate capture taken at identity-resolution time and retained with the run; `RecordCorrectionWire[]` recorded in the run's evidence and printed on its receipt beside the value each replaced; a `continue-with-data` command that patches the checkpoint and resumes the same run under the same id; and the `data`-placement action policy above, including the parked exclusion. **Gotchas.** `min-h-0` on a rail SECTION lets it shrink below its content inside the `overflow-y-auto` column, so the Data ledger rendered ON TOP of Provenance — sections there want `shrink-0`, not `min-h-0`. And `playwright-cli click` presses an element's CENTRE, so clicking a queue-row button whose middle holds a delegated-child chip navigates to the child instead of selecting the row (reach `sep-dana` through the Person Lookup panel's `Separations · Dana Whitmore` back chip). Verified at 1280×720 in both themes against the real built bundle: `.screenshots/panel-rework/`. Pure seams pinned by `tests/unit/dashboard/rebuild-demo-data-surface.test.ts` (8). Gates: `typecheck:all`, `test` (4369), `test:architecture` (137), `eslint src/dashboard/components/dev`, `build:dashboard` — all green.

- **2026-07-27: the rebuild demo's four-wave redesign — a togglable theme PAIR, a Workflow Panel that costs no column, a three-column detail region that took Data and Evidence OUT of the tab set, and a queue that explains its own rows (`dev/rebuild-demo/ds/{tokens.css,theme.ts,primitives-overlay.tsx,primitives-layout.tsx}`, `DemoShell.tsx`, `DemoLogPanel.tsx`, `DemoContextRail.tsx`, `DemoEvidence.tsx`, `DemoQueue.tsx`, `demo-catalog.ts`, `RebuildDemo.tsx`).** Commits `1d656f76`..`a380406c`; the doc amendments they forced are `55d70789` (`docs/rebuild/03-tracker-dashboard.md` §9 — **D11** amended, **D19** gains (d), **D21** new). **This one entry replaces the four passes' worth of separate entries** — waves 2–4 deliberately deferred writing their own so the programme lands as one lesson rather than five overlapping ones. Two operator complaints drove all of it, and they are the same complaint from two directions: *"as we add more stuff, the log panel gets so small that i can barely see the logs"* (vertical) and *"i feel like we have too much clutter right now. maybe its because i dont understand what is being done"* (which is a **diagnosis, not a volume complaint** — some of the felt clutter is UNEXPLAINED, not excessive). **(1) The palette became a PAIR, and the token contract is what makes it honest.** One dark theme ran eight hues at once (four status + four categorical log accents) with `Running` — the most common thing on screen — holding a blue of its own. There are now two themes, each authored as its own contiguous block in `ds/tokens.css` and NOT as a diff against the other: **Graphite Warm** (warm near-black; depth from surface + hairline) and **Paper Ink** (tinted page, white cards; depth from a shadow). Four of the five hues are RE-PICKED between them rather than lightened, because every dark swatch fails 4.5:1 as body text on white. **`Running` / `Queued` / `Cancelled` are hueless** — a spinner is a stronger signal than a colour, and a hue spent on the commonest status is a hue spent everywhere; `--log-cyan|teal|slate` retired to a neutral ink ramp (a write reads strongest, a read a step back, navigation quieter) and `--log-violet` resolves to warning amber, because "unconfirmed write" was never a category. **The contract every hue now carries: `--ds-<x>-fg` is the value rendered as TEXT (measured at 4.5:1 on page, on surface AND on its own rendered tint) and `--ds-<x>-mark` is the raw swatch for a dot / rail / bar / fill** — they are different values for the same hue and using `-mark` as text is the bug the split exists to prevent. `--ds-control-border` is new and held to 3:1, because a control's outline is what identifies it as a control. On Graphite Warm the accent is amber, the same family as `warning`, so it is deliberately NOT the action colour there (the primary button is the highest-contrast neutral fill and the amber lives on `--ds-accent-mark`); Paper Ink has no such collision, so its indigo accent IS its action. **(2) `Popover` — the primitive the explanation had nowhere to live without.** `DESIGN.md`'s ❌ list (currently :289) forbids load-bearing information behind hover alone — a tooltip is invisible to touch and to anyone who never points at it — and the system had no other home for an explanation. `Popover` (`ds/primitives-overlay.tsx`, on the already-present `@radix-ui/react-popover`) **opens on CLICK**, so it is reachable by pointer, touch and keyboard; `title` is required and becomes the accessible name (`hideTitle` keeps the name, drops the heading row); it is deliberately NON-modal, because an explanation should not lock the page behind it. It **registers modal presence** on the same terms as Dialog/Drawer — a `danger` toast never auto-dismisses and the viewport is `fixed bottom-right`, so a popover anchored to a row near the bottom of the queue lands under exactly the surface that eats clicks. **(3) The shell gave 73px back, and the Workflow Panel stopped costing a column.** At 1280×720 five bands stacked above the panels and left them **469px**. Three were carrying one idea each, so they are gone as bands and kept as CONTENT: the view-title bar is deleted (the workflow name is now the Queue Panel's own `h2`; the row count was a second rendering of the Status Bar's `All` pill; the keyboard legend moved into a Popover behind the Top Bar's shortcuts button, which until then did literally nothing), and the run-start band folded into the queue toolbar as one primary control with a three-door menu. **Chrome above the panels 190px → 117px; each panel 469px → 542px.** The Workflow Panel now has three persisted modes cycled with `w`: **floating** (default — a window over the panel region, costing no column), **icon** (nothing drawn over the content; the launcher carries the workflow's own 2-char trace-id prefix so it is never an anonymous glyph, plus the day's whole `Needs you` count across EVERY panel), and **sidebar** (docked 200px). **`All workflows` is retired** — `ALL_WORKFLOWS` deleted, `rowsForWorkflow` always filters, `DEFAULT_WORKFLOW` is read from the registry so a rename cannot point it at nothing. An operator works one workflow at a time, and a queue mixing fourteen workflows forces every row title to carry a workflow label to stay legible (which is the same redundancy that later made the per-row workflow chip worth deleting). Two knock-ons the sentinel used to absorb: opening a catalog example lands in that row's OWN panel, and a date change re-anchors the selection inside the panel you are looking at. `countRows` — the one counting path feeding rail badges + Status Bar + queue header — is untouched by any of this. **(4) The detail region is THREE columns, and Data left the tab set.** Measured at 1280×720 the Log Panel stacked NINE bands over one scrolling body (run header, delegation link, linked-children chip, outcome bar, identity strip, attempt selector, gate banner, timeline, evidence strip, tab bar) — 380–410px of chrome over a 542px panel, leaving the stream ~125px, because only the tab body carried `min-h-0 flex-1 overflow-y-auto` and every band was subtracted from the one thing the panel is opened for. **The split is by READING PATTERN, not by importance**: LIVE STATE (what the run is doing and what it needs from you — read continuously) stays in the centre; REFERENCE (what it read and wrote, what it captured, who asked for it, which attempt, what delegated it — read on demand) moves to a **348px context rail** (`--ds-w-context-rail`, `DemoContextRail.tsx`). Nothing is deleted and nothing hides behind a hover. **What does NOT move: the gate banner and the failure record**, ever — `Waiting on you` and `Failed` are the only two things allowed to shout, and a decision parked in a collapsible rail is a decision that never gets made. So: **Data** is a rail section (a compact grouped read/write ledger, values in `dsText.nums`) plus an **`Edit & re-run` Dialog**; **Evidence** is a rail section of real tiles (kind, label, the step it was taken on, the clock) instead of the 52px strip that gave a capture a 76×40 chip and a three-character label; identity strip, attempt selector and delegation links are rail content. **Tabs are now `Logs · Review · Receipt` (+ `People` on a group) — Run 2 · Review 3 · Group 3 · Member 2**, and `DemoTab` + `tabsFor` drop `"data"` entirely so no dead tab id is reachable (`detailSurfaces` re-derives from `tabsFor` at projection). **Every D19c semantic survives byte-for-byte** — reads editable, writes shown and never editable, staged still staged, unconfirmed still unconfirmed, the `Load a prior run` / `Start a run from this data` footer, `editPolicyFor` unlock rules with the reason always shown, CAS on the checkpoint generation, the audited freshness override. Only the HOME changed, because editing is a task and reference is not. **Tab body at 1280×720, before → after:** gated packet group 130→217 · gated run 123→213 · gated review run 204→335 · failed run 204→335 · typed-list group 215→272 (229 in a 728px column with the rail collapsed). Also here because it is the same restructure: the outcome line is SUPPRESSED wherever the gate banner already carries that sentence and the buttons that answer it (two bands saying the same thing is how a dense panel teaches an operator to skim past both); it keeps its real job, which is runs with no gate. **(5) The timeline is equal-width — a deliberate REVERSAL, ratified as D21.** Operator, verbatim: *"all the timeline elements should have equal sizes doesnt matter the time."* Every step segment is the same width, the duration prints as a label beneath it, the gate segment is hatched and equal-width with the TRUE age printed as text; `×N` retry markers and the dashed not-yet-reached treatment carry over. Removed with the maths: `MIN_SLOT_SEC`, `slot()`, `stepTotal`, `gateSlot`/`gateClamped`, the per-step inline width and the wedge's ≤1.5× clamp. **Do not restore proportionality on no-fabrication grounds** — a true proportional 34-minute gate beside three minutes of work is 91% of the track, and at 91% the step labels crush to `3.¹2 4..`; equal widths claim nothing about duration precisely BECAUSE the duration is printed beside every segment. That argument has been made and answered in D21. **(6) The queue explains its own rows, every Group Row reads the same at every size, and the column gives 70px back.** `rowExplanationOf(row)` (`demo-catalog.ts`) returns three short sentences (what the row is doing · what opening it shows · why it is its own row) built from the naming layer the catalog already owned: `doing`+`why` key on the row VARIANT (8), `panel` on the panel KIND (4) — so it is **DERIVED, never authored per fixture**, a new fixture inherits correct copy with nothing to write, and the sentence cannot drift from the row. SCOPE is the one non-shape input: a standalone OCR run (no `reviewOf`) keeps the same `doing`/`panel` as a delegated one and swaps its `why` to "approving would release no work", rather than promising a gate that is not there. Pinned by `tests/unit/dashboard/rebuild-demo-row-explanation.test.ts`. The trigger is a **`Popover`, not a tooltip**, it EXPLAINS and never HIDES (status, gate age, counts, error, trace and every command stay on the row), and it is **always rendered** — quiet at rest is not the same as absent — staying lit via `data-[state=open]` so the surface never floats free of its row; a new `xs` (20px) `IconButton` size was added TO the primitive so the ⓘ sits on the chip line and costs the queue zero vertical space. **The 41+ status matrix is gone** (D11 amended): the operator saw the 50-member I-9 roster render as a grid of cells where the 18-person work-study group shows named lines and read it as a different KIND of row. Three rungs now — 1–3 inline · 4–12 compact · 13+ well — and every group is count strip → status counts → member well (name · detail · EID) → `Open all N people`. Nothing was lost: the well is capped by `--ds-h-member-well` (**136px ≈ 5.67 rows** — the deliberate half-cut row IS the depth cue, which is why it is not 144), members are attention-first so the top of the well IS the attention list, and the drill-in survives. **The queue is 400px in the 1180–1479 band (470 at ≥1480), and that number is measured.** At 1280 the region was queue 470 + rail 348 + centre **414**, so the review's page-beside-fields layout stacked and the extracted fields — the point of that surface — went below the fold. The review's floor is a **464px centre** (label + value + provenance chip + confidence on one line) and centre = 884 − queue at 1280, so 400 is the LARGEST queue that keeps the review side by side (measured after: **centre 484**, review 184 + 298). The review body gained a second container-query rung (0.62fr from 464px, 0.85fr from 680px) instead of stacking. **The load-bearing discovery:** the per-row workflow chip repeated on every row a word the panel header, the rail badge and the Status Bar had ALL already said, and on a 400px column it cost `Oath_Packet_Summer.pdf` a hundred pixels of its own filename (rendered "O."). Gating it on `state.panelWorkflow` (undefined in the component gallery, so the chip returns there with no flag) gives the title **140px at a 400px queue — more than the incumbent 470 gave it (84px)**. **Stated cost:** at 1280 no width satisfies both; a queue rendering that filename whole needs ~475px, which puts the centre back under the review's floor — the full name stays in the row's `title`, the footer's trace id and the panel header. **GOTCHAS — the ones that cost real time.** **(a) A layout switch INSIDE the detail region must key on the COLUMN, not the window.** The same 1280px viewport gives the centre 414px with the rail open and 728px with it collapsed, so a `min-[Npx]:` media query fires at the wrong moment in BOTH directions. Caught in the act: the two `Write parked` resolutions being forced side by side into a 414px column, each a ~200px box holding a two-line sentence about whether a real UCPath termination exists. Container queries for anything inside the region; the two viewport thresholds that remain are deliberately different (**1180** splits queue │ detail, **1280** splits the detail cell into shape · detail · context, **1480** moves the shape into the centre — 1480 = 470 + 348 + gaps + padding, which leaves ~590px, the width at which a six-segment timeline still prints readable labels). **(b) The theme attribute must be stamped on `<html>`, `<body>` AND the demo root, in a LAYOUT effect.** The shipped dashboard hardcodes `class="dark"` on html and body and a `.dark` ancestor re-scopes every token, so `data-demo-theme` selectors are written to outrank it *on the element carrying it*; every overlay portals to `<body>`, which is why body needs it too. A plain `useEffect` runs after paint, so a reload with `light` persisted painted one frame of Graphite Warm — `useLayoutEffect` commits before paint. **(c) A palette swap is a CUT, not a transition.** Every element with `ds-motion` already transitions `color`/`background-color`, so switching themes crossfaded those elements over 90–140ms while everything else snapped — a ragged wipe. `useDemoTheme` sets `data-demo-theme-switching` for the single frame the new palette lands in, zeroing the four duration tokens (the same switch `prefers-reduced-motion` throws), which removes every transition in the system with no `!important` and no specificity fight. **(d) A popover must scale out of Radix's RESOLVED anchor, not a hand-picked origin.** Entry motion keys off `data-side` (the resolved side) and `transform-origin: var(--radix-popover-content-transform-origin)` — with `center` or with the `side` PROP, a collision-flipped popover animates AWAY from its own trigger. Related sizing rule: the row ⓘ uses `md`, not `lg`, because a 380px surface in a 400px queue column is collision-shifted on every open, which keeps moving the point it scales out of. **(e) The Workflow Panel is deliberately NOT built on Popover or Dialog.** Both register modal presence, which makes the toast viewport step aside and go inert for as long as they are mounted — and floating is the DEFAULT state, so the demo would have booted with its toasts permanently inert. It composes the floating tokens directly and owns the three things Radix would have given it: Escape dismisses when the caret is inside (the shell's own Escape ladder minimises it AFTER drill-out, so drill-out stays reachable); an outside pointerdown dismisses in the **CAPTURE** phase, so the click that dismissed still reaches the row it landed on; and focus is **scoped, not seized** — Tab cycles inside once the caret is in, the launcher gets focus back only when focus WAS inside, and never on first paint. **(f) `align-items: stretch` only stretches an item whose cross size computes to `auto`** — so the obvious `h-full` on a Session Card opts it straight back out. The cards carry no height at all; the row is `items-stretch` with `mt-auto` on the footer, so the slack lands between the browser tiles and the footer and every card's time, step and `Stop` sit on one line. That slack is left EMPTY on purpose: an idle worker genuinely has less to say than a blocked one, and padding it with filler dresses it up as busier than it is. **(g) `flex-wrap` inside a fixed `--ds-h-bar` silently CLIPS the second line** — the queue toolbar went `nowrap` + `overflow-x-auto` once select mode plus four bulk commands could reach a second row. **(h) Folding a band away can take the page's only `h1` with it.** Deleting the view-title bar left the document with no outline root — a real screen-reader regression, not a cosmetic one. The Top Bar's app name took it; heading LEVEL is the outline and has nothing to do with type size, so it cost no pixels. **(i) An `aria-label` REPLACES a button's contents outright**, so the launcher badge's number was announced to nobody until the count was folded into the label — the one number that control exists to carry. (A badge that vanishes at zero also reflows the whole action bar every time the count crosses it: it dims and steps down to neutral instead, because a solid-amber zero would read as a standing demand.) **(j) A timeline segment gets a hover tint but deliberately NO press dip** — it is a disclosure trigger, not a command, and a dip promises a commit that never happens; its hover card anchors to the nearer edge, since an equal-width segment can be narrower than the 240px card. Everything that IS a command got the 1px dip (evidence tiles, toolbar controls). **(k) Known gap, stated so it is not "fixed" by accident:** members inside a compact/well list are preview LINES, not row cards, so they carry no ⓘ; the inline (1–3) rung does. Fifty ⓘs in a scroll well would be the clutter the affordance exists to remove. **(l) `dashboard:prod` caches the built HTML at boot and `playwright-cli navigate` to the same URL does not remount a SPA** — after `npm run build:dashboard` you must restart the server AND `playwright-cli close`, or you screenshot the old bundle.
