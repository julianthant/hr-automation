## Lessons Learned

- **2026-07-26: the rebuild demo's POLISH pass — three shared shapes replaced twenty surfaces' worth of local invention (`dev/rebuild-demo/ds/primitives-layout.tsx`, every `Demo*.tsx`).** The Tier-1–4 surfaces were built by six agents in isolation: individually good, collectively inconsistent. The fix was not restyling, it was NAMING the three shapes every surface kept re-drawing. **(1) `Refusal` — the product declining on purpose, which is not a failure.** Seven call sites (enqueue rejected, the intake's validate + manifest blocks, a park-resolve fence miss, a search lookup that could not run, an env-owned setting, a refused bump) each drew their own; the intake alone said `Blocked — no-valid-rows` in one stage and `This plan cannot start — no-valid-rows` in the next, for the same block. A `Refusal` always carries its `code` (a refusal the operator cannot quote is one they cannot get help with) and states what was NOT done, and it uses **`ShieldAlert`, never `TriangleAlert`** — the triangle means something broke, the shield means something was refused, and that one icon swap is what makes the two readable apart at a glance. **(2) `MetaLine` — the provenance line.** Four surfaces reached for a raw `font-mono`, which is NOT `dsText.nums`: it drops the tabular figures, so the settling probe's clock jittered as it ticked. Segments join with ` · ` and empty ones drop out, so a conditional fact leaves no dangling dot. **(3) `BulletList`** — six places rendered fact lists as `<p>· {item}</p>`; a literal middle-dot is spoken aloud by a screen reader and carries no list semantics. Also unified: `DialogFooter` gained a `meta` slot (hand-rolled `mr-auto` on five dialogs, none of which truncated, so a long filename shoved the actions off the right edge), the dismiss verb (**`Cancel`** when the surface was building something that will not now exist, **`Close`** when it was only showing you something — the intake and the bump said Close for a build flow), and `PageHeader` for the three full-page takeovers. **The one type lesson:** `code` is optional on both result unions because `applied`/`conflict` have none, so a call site cannot reach it — and `result.code ?? "unknown"` is exactly the banned nullish-literal fallback. `hasRefusalCode()` (in `demo-commands.ts`) is the type predicate that lets the code be read honestly; where a refusal genuinely arrives without one the surface SAYS so rather than inventing it. The fail-loud rule applies to pixels. Gotchas: **`playwright-cli navigate` to the same URL does not remount a SPA** — the demo kept screenshotting whatever dialog was already open, so a fresh `close` + `open` is the only reliable reset; and `dashboard:prod` caches the built HTML at boot, so a rebuild needs a server restart too. Before/after: `.screenshots/polish-new/`.
- **2026-07-26: the rebuild demo's TRUST surfaces — full `RunEvidenceReceipt`, full `FailureRecord`, and a working evidence lightbox (`dev/rebuild-demo/demo-evidence-wire.ts`, `DemoReceipt.tsx`, `DemoFailure.tsx`, `DemoEvidence.tsx`).** Tier 4a of `docs/rebuild/reviews/demo-feature-plan-2026-07-25.md`. **`demo-evidence-wire.ts` is the trust half of the wire contract, shaped as a FETCH-BY-ID store** (doc 12 §2.1–2.4 + plan §1.2: the row carries `evidence.receiptId`/`failureId`, the record lives in diagnostic storage) — so a row with no id simply has no surface, and nothing renders a record it was not served. Four mechanics are worth keeping: (1) **a receipt never authors its own identity** — trace/attempt/actor/confidence/observations/outputs are read off the row at fetch time, so a record cannot drift from the run it describes (per-member confirmations are keyed by MEMBER ROW ID and the names/EIDs come from those rows, never re-typed); (2) **`DemoActionEvidence` is a discriminated union so a `commit`/`prepare` CANNOT be authored without a `readBack`, and a non-verified read-back is type-forced to carry its reason** — that is what makes "OnBase returns no keyword set, so these were never read back" a rendered sentence instead of a silence; (3) **the verdict is derived then re-checked** — `deriveReceiptResult` maps status+members (a failed run holding verified member writes is `partial`, the word doc 12's enum exists for) and `receiptInvariant` re-applies "verified-done requires verified confidence, every criterion met, no unfinished member", with the surface printing the DEFECT rather than the green headline if it fails; (4) **the lightbox renders capture METADATA and says the bytes are not in the corpus** — a drawn stand-in of a UCPath page on an evidence surface is the exact fabrication the rebuild exists to prevent. Failure detail leads with **what is half-done** (`writeState`) before anything is expanded, lists every remediation with its safety verdict **including the blocked ones and why** (a hidden button never answers "why can't I just retry"), and mirrors a linked child's error verbatim per D13. Gotchas: **`DialogBody` takes no DOM props, and Radix moves focus to the header's close button, so lightbox arrow keys must be a window listener in the CAPTURE phase with `stopPropagation`** — otherwise the shell's own j/k/arrow queue navigation moves the row behind an open modal; and the packet receipt's `result` cannot be authored per fixture without drifting from the rollup, which is why it is computed. Verified headless at `?view=rebuild-demo`: `.screenshots/trust/01–09`.
- **2026-07-26: a `ds` toast could swallow a dialog's primary button — fixed in the primitive (`ds/primitives-overlay.tsx`).** The toast viewport is `fixed bottom-right` at `dsLayer.toast`; at 1280×720 that lands exactly on a dialog's footer, and a `danger` toast never auto-dismisses, so a persistent failure toast ate every click on the primary button with nothing on screen explaining why. Measured on the parked-write dialog: primary `x 808–1003`, right-anchored viewport `x 904–1264`. **Fix: while any Dialog/Drawer is mounted the viewport re-anchors bottom-right → bottom-LEFT (footers are right-aligned with the primary last by design rule, so the left gutter is the one region a decision never occupies) AND every card goes `pointer-events: none` with its controls disabled** — the geometry alone is not enough, because an `xl` dialog is wider than any gutter; inert cards make interception impossible at any size. Nothing is hidden (the text stays legible above the scrim) and the cards go live again when the modal closes. Modal presence is a **module-scoped counter read through `useSyncExternalStore`**, incremented by `DialogSurface`/`DrawerSurface` (they only mount while open), so no provider nesting is required between the toast provider and the dialogs. **Superseded 2026-07-26 (polish pass):** the registry is no longer `ds`-only — `useDsModalPresence()` is exported from `ds/primitives-overlay.tsx` for exactly this, and any dialog built on another primitive must call it from a component that MOUNTS ONLY WHILE OPEN (the count is keyed to mount, not to an `open` prop; Radix already unmounts `DialogContent`'s children on close). `RenameRunDialog` calls it; **`ConfirmCommandDialog` in `DemoActions.tsx` still does not** — it needs the same two lines. `data-ds-toast-viewport="aside|default"` is the hook a headless check asserts on. Worth knowing when you measure it: for the two `size="sm"` app dialogs the overlap is latent at desktop widths (at 1600×1000 the toast misses the footer entirely; at 1100×700 it clips only the right edge of the primary) — the dialogs that were ACTIVELY blocked are the wide `ds` ones, which already register. Wiring the last one closes the class rather than fixing a daily failure, which is the honest way to describe it.

- **2026-07-26: the rebuild demo gained its PERIPHERY — Settings, storage health, archive-on-version-bump, executor capacity, the read-only Explorer and the activity report (`dev/rebuild-demo/Demo{Settings,VersionBump,Archive,Explorer,ActivityReport}.tsx`, `demo-{settings,archive,explorer,report}-wire.ts`).** Tier 4b of `docs/rebuild/reviews/demo-feature-plan-2026-07-25.md`. **Settings is built around PROVENANCE, not values** — precedence is `env > settings.json > code default`, so every leaf carries all three layers, the server says which won, and the losing layers render struck through; a leaf the environment owns is `editable: false` with a disabled control and an explicit "override anyway" that returns the server's typed refusal (a Save that silently loses to an env var is the worst version of that screen). A second lock reason exists for leaves that are not settings at all (`operator.actor`) — reusing the env-precedence copy for those read as nonsense. **Storage health serves TWO authored snapshots**, so degraded is a served state rather than a UI mood: `DemoStorageBanner` renders app-wide from the snapshot's own `stillWorks`/`blocked` lists, and `submitSettingChange` refuses every write while read-only. **Archive-on-version-bump (§6.6 / doc 03 §10.2) is made mechanical, not a UI guard:** `deriveBumpPlan` reads the SAME corpus and the SAME `effectiveStatus` the queue reads, so the blocker list cannot drift from the visible queue, and `submitVersionBump` refuses on its own derived output — the primary button is never disabled when blockers exist, because the refusal (naming each queued/running/waiting/parked run, calling out parked writes specially) IS the feature; there is no force arm. Archived runs are self-contained (final row + receipt + evidence pointers + immutable input + ledger) so the archive renders with zero old-version code, the ledger is shown but never archived, and relaunch mints a FRESH current-version run. **Session Cards** gained lanes, per-system in-use/cap and a named waiting-on-lease note ("Waiting 4m 25s for the ucpath lease — held by Separations se-140211-9f3a"); the I-9 fixture is authored alive+healthy+six-queued+stopped, because without the note that card is a lie told with a spinner. **Explorer is read-only by ratification (Q14)** and follows one rule: *the graph is authored, the overlay is DERIVED* — node ids ARE the separations descriptor's step labels, so a real `DemoRow.steps` array matches onto them, and "not reached yet" (run in flight) is kept distinct from "no step recorded — not on this run's path" (run ended). **The activity report** puts its counterweights first and uncollapsible: outstanding rows named beside finished ones, the error rate printing its denominator, and hours-saved labelled ESTIMATE in the headline tile rather than a footnote (only finished runs contribute — a failed run cost time). Wiring: the Top Bar gear opens Settings (`DemoShellView` gained four takeover views that are deliberately NOT in the 3-entry switcher — seven segments in a 44px bar is unreadable), and Settings' "Full-page views" nav group launches Archive/Explorer/Report, mirroring the Workflow Editor takeover. Gotchas hit: **`dashboard:prod` caches the built HTML at boot** — after `npm run build:dashboard` you must restart the server AND `playwright-cli close` the session, or you screenshot the old bundle and think your edit did nothing (a query-string cache-bust is not enough); and **the bottom-right toast viewport intercepts pointer events over any `PanelFooter` right-aligned button** — a `danger` toast never auto-dismisses by design, so headless runs must dismiss it before clicking a footer primary. Verified headless at `?view=rebuild-demo` — `.screenshots/periphery/01`–`19`.
