# Handoff — Harden I-9

**Date:** 2026-07-01  **Wave:** 1 (parallel; own git worktree + branch `feature/harden-i9`)

## Task summary

The I-9 system (`src/systems/i9`) has three "act on a timer, then trust the result" bugs that produce silent wrong answers: a search that reports **not-found for a signer who actually exists**, a create that reports **success when the server actually rejected it**, and a worksite selector that **throws for a valid department** because it reads before options render. Plus the create-form selectors carry **no `// verified` date** at all. The fix pattern is the campaign standard: **wait for the specific target to be visible/ready, then assert the landed state** — never read counts on a fixed sleep, never treat "no exception" as "succeeded."

## Audit findings to fix (the actionable seed)

- [ ] **`src/systems/i9/search.ts:102`** — a bare `waitForTimeout(1_000)` is the **only** wait before `parseSearchResults` reads `rows.count()`. If results haven't rendered yet, `count()` is 0 → **false `not-found`** for a signer who exists. Fix: wait for `resultRows.first()` to be **visible** before counting; only conclude not-found once the results container has settled.
- [ ] **`src/systems/i9/create.ts:124-138`** — returns `{success:true}` **just because two clicks didn't throw**. A server-side validation failure then reads as success. Fix: assert a **post-create success state** (the new record's URL / an on-page confirmation), not the absence of a click exception.
- [ ] **`create.ts:206-217`** — `selectWorksite` reads `option.count()` **before options render** → throws **"No worksite found"** for a valid department. Fix: wait the first `<option>` visible/attached before counting; fail loud only after options have had a chance to populate.
- [ ] **`src/systems/i9/selectors.ts:83-114`** — the create-form field selectors carry **NO `// verified` date**. Re-verify them live via `playwright-cli`, stamp `// verified 2026-07-01`, then `npm run selectors:catalog`.
