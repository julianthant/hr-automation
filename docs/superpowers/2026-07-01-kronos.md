# Handoff — Harden Kronos (old + new)

**Date:** 2026-07-01  **Wave:** 1 (parallel; own git worktree + branch `feature/harden-kronos`)

## Task summary

Kronos (both the legacy **old-kronos** report engine and **new-kronos** navigation) is the **worst fixed-sleep cluster** in the codebase and carries the **stalest selectors**. The sleeps aren't just slow — they hide correctness bugs: a fixed pad before reading the report grid means a **stale "Complete" row from a PREVIOUS employee** can be mistaken for the current one (→ wrong PDF), a fixed pad before the frame loads means format dropdowns get **silently skipped** (→ wrong-format report), and a fixed pad after "Apply" means the code **parses the previous pay window**. The fix pattern across all of them is the same: **poll for the specific readiness signal (status / frame / date-input), and assert the pay-period switch (button text) BEFORE reading the grid** — never read on a timer.

## Audit findings to fix (the actionable seed)

### old-kronos
- [ ] **`src/systems/old-kronos/reports.ts:506`** — 2s pad before `collectReportRowIds`. A stale **"Complete"** row from a previous employee's run looks new → the workflow downloads the **WRONG PDF**. Fix: poll for the freshly-submitted report row's status to become Complete (identity/timestamp-anchored), not a blanket 2s.
- [ ] **`reports.ts:472`** — 5s pad before `page.frame("khtmlReportWorkspace")`. If the frame is still null, the **Actual/Adjusted** and **Output-Format=PDF** dropdowns are silently skipped → **wrong-format report**. Fix: poll until the frame is attached, then set the dropdowns and assert they took.
- [ ] **`navigate.ts:137`** — 1.5s pad before `dateInputs.count()`. If `< 2`, `setDateRange` **returns early** → **wrong pay window**. Fix: wait for both date inputs to be present/visible, then assert count == 2 before setting; fail loud if not.
- [ ] **Stalest selectors — re-verify + tighten** `selectors.ts:158` (`text=Reports .first()`), `:146`, `:125`, `:84` (all last verified **2026-03-16**). The `text=Reports .first()` is exactly the kind of loose/positional selector that mis-clicks; re-map via `playwright-cli`, tighten, and bump `// verified 2026-07-01`, then `npm run selectors:catalog`.

### new-kronos
- [ ] **`navigate.ts:942`** — 2.5s pad after **Apply** → the code parses the **PREVIOUS** pay window. Fix: assert the pay-period switch landed (see below) before parsing the grid.
- [ ] **`navigate.ts:464`** (and the older **`navigate.ts:410`**) — 5s pad with **no switch assertion**. Fix: poll + assert the switch, don't sleep.

### Fix pattern (all of the above)
Poll for the concrete readiness signal (report status row / frame attached / date inputs present), and **assert the pay-period switch by reading the period button's text** BEFORE reading the grid. Reading the grid must be gated on "the period I asked for is the period now shown."
