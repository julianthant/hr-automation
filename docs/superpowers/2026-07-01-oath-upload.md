**Date:** 2026-07-01  **Wave:** 1 (parallel; own git worktree + branch `feature/harden-oath-upload`; requires Wave 0 OCR-orchestrator hardening landed first)

## Task summary
Harden the **oath-upload** workflow's OWN logic against flakiness, then live-verify end-to-end. This is its OWN workflow, not the shared OCR service: a **born-at-upload ServiceNow HR ticket** (option A — a real daemon `single` task, deliberately **NOT** an operation row) that walks `wait-approval → wait-signatures → servicenow-auth → open-hr-form → fill-form → submit` as ONE row (`inputSubject: "pdf"`, `code: "ou"`). Full mode files ONE HR ticket per PDF after every per-signer `oath-signature` row finishes; `upload-only` mode files directly with no OCR/signers. Harden its **ticket idempotency** + the **walk** (the wait/approval/submit sequence) — distinct from the shared orchestrator.

**Scope boundary:** OCR is a SHARED service — the OCR orchestrator (`src/workflows/ocr/orchestrator.ts`) is hardened separately in **Wave 0** (`2026-07-01-ocr-orchestrator.md`). This task covers oath-upload's OWN handler + ServiceNow filing, NOT the orchestrator (you inherit Wave-0's fixes). The delegated OCR prep under the ticket runs on the (Wave-0-hardened) orchestrator; you harden the ticket's walk around it.

## Audit findings to fix (the actionable seed)
Focus on the **ticket/idempotency + walk** — the born-at-upload contract is subtle and already carries several fixed-bug scars (ISS-001 content-dup, E2E-006/008/010, approval-empty). Re-audit against flakiness:
1. **Idempotency across retry + content re-upload.** The submit guard is `findPriorTicketForSession(sessionId, pdfHash, trackerDir)` (keys on stable business identity, not runId) plus the `/api/ocr/prepare` content probe `findPriorOathUploadTicket`. Confirm a retry (new runId, replayed from step 0) and a same-content re-upload BOTH resolve to the existing `HRC…` ticket and never file a SECOND ServiceNow inquiry — and that a flaky/slow tracker read of prior rows fails **safe** in the right direction (a missed prior row must not silently file a duplicate; verify which way the fail-open goes and whether it's correct here).
2. **The cross-daemon waits.** `wait-approval` (`subscribeToApproval({ workflow:"ocr", sessionId })`) and `wait-signatures` (`watchChildRuns({ workflow:"oath-signature", expectedItemIds })`) are long, cross-daemon, cross-process (JSONL backstop). Audit for: a flaky wait that resolves early/empty (already guarded: zero signer rows must THROW, not file an empty ticket — confirm it still holds), a missed terminal event leaving the row hung, and correct THROW-without-filing on any signer `missing`/`failed`/`cancelled`. Confirm both waits honor `ctx.signal` (tree-scoped cancel — E2E-010) so a cancelled ticket unwinds cleanly.
3. **Submit / ticket-number capture.** `submit` scrapes the new ticket number from the redirect URL (`?id=ticket&number=HRC0XXXXXX`). Confirm it waits for the real post-submit navigation before scraping (a premature read → blank/wrong ticket number stamped on `data.ticketNumber`), and that a failed capture doesn't leave a filed-but-unrecorded ticket.
4. **Sibling low-pri (fix while you're here):** `src/workflows/sharepoint-download/handler.ts:232,297` fire-and-forget `void startSharePointDownloadJob(...)` — a throw BEFORE the inner `try` (e.g. building `workflowInput`) is an **unhandled promise rejection with no queue advance** (the job silently vanishes; `startNextQueuedJob` never runs). **Fix:** `.catch(...)` the kickoff so a synchronous/early throw is logged and the queue advances (or wrap the whole body so `finally { startNextQueuedJob() }` always fires). Small, isolated — safe to land in this worktree.

## How to start + test data (live-verify)
- **Start path:** upload run via **RunModal** — upload a paper oath **PDF** + the roster xlsx. The modal exposes `oathUploadMode` (**full** vs **upload-only**) and a **dryRun toggle**. Open `:39NN/?wf=oath-upload`, Run → the oath-upload run modal.
- **full mode:** the ticket is born at upload, delegates OCR under it, fans out signer rows to the oath-signature daemon, waits on them, then files. To exercise the walk end-to-end without a real ServiceNow submit, use **dryRun** (skips the actual file/submit). **upload-only mode:** skips signer waits, files the ticket directly — use dryRun to walk the ServiceNow form without submitting.
- ServiceNow auth is deferred to the `servicenow-auth` step (after the waits); Duo clears hands-off. **Read the key screenshot** — confirm the HR Inquiry form is filled with the right subject/description/category and the PDF attached before the (dry-run) submit; for full mode confirm it only reaches ServiceNow AFTER the signer rows finished.
- **Test data:** a small oath PDF + roster xlsx. To exercise idempotency (#1), re-upload the SAME PDF content in a fresh session and confirm `/api/ocr/prepare` returns the structured `409 duplicate` (no second ticket). To exercise #2's empty-approval guard, approve an OCR set where every record is EID-less → confirm it THROWS `approval-empty` and files nothing.
